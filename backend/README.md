# SIH 2026 — National AI Weather Intelligence & Truth Engine

## 1. What the system does
This is the backend prototype for the National Weather Big Data Analytics Platform (SIH26069). It ingests real-time weather observations from various sources (citizen, official, social media, APIs), verifies them using an AI Truth Engine, fuses them, and clusters them into distinct weather events. It then calculates a risk score and generates real-time alerts.

## 2. Architecture
- **API/Ingestion:** FastAPI
- **Streaming Pipeline:** Redpanda (Kafka-compatible), `aiokafka` (for stream processing)
- **Database:** PostgreSQL + PostGIS
- **Real-Time Delivery:** Server-Sent Events (SSE) via FastAPI

## 3. Data Flow
1. **Collect:** `POST /api/v1/observations` -> placed into `weather.raw` topic.
2. **Pipeline Processing:** `weather.raw` -> `cleaned` -> `verified` -> `classified` -> `fused` -> `clustered` -> `predicted` -> `risk` -> `alerts`.
3. **Storage:** Saved to PostGIS database.
4. **Broadcast:** Alerts and events pushed to frontend via SSE.

## 4. Truth Engine
A deterministic, 7-factor explainable AI evidence engine that scores reports from 0-100 based on source reliability, location/timestamp plausibility, weather/nearby corroboration, and media presence.

## 5. Clustering
Density-based clustering using **HDBSCAN** to group multiple geospatial observations (e.g., citizen reports) over a timeframe into a single localized real-world event.

## 6. Prediction
A mathematical baseline (designed to be replaceable by an ML model like XGBoost) calculating the probability of conditions worsening over a 3-hour window.

## 7. Risk Calculation
An impact scoring engine combining event severity, predicted probability, and geographical exposure, categorizing events from LOW to CRITICAL.

## 8. Alert Generation
Prevents duplicate alerts and issues warnings based on a combination of risk level, truth confidence, and report growth velocity.

## 9. API Endpoints
- `GET /health` - System health
- `POST /api/v1/observations` - Submit an observation
- `GET /api/v1/events` - Retrieve active events
- `GET /api/v1/events/stream` - SSE stream of updates
- Swagger UI at `/docs`

## 10. How to Run
```bash
# Start Redpanda and PostGIS
docker-compose up -d

# Install dependencies
pip install -r requirements.txt

# Run the FastAPI server
uvicorn app.main:app --reload
```

## 11. How to Insert an Observation
Use the Swagger UI at `http://localhost:8000/docs` to test `POST /api/v1/observations`.

## 12. Real-Time Stream
Connect to `http://localhost:8000/api/v1/events/stream` using an EventSource client (or curl) to watch real-time updates.

## 13. Mock Data
**Note: Mock data is synthetic and used only for demonstration purposes.** It is generated by `scripts/seed_demo.py` and `scripts/run_demo.py`. It is clearly flagged with `is_mock: true`.

## 14. Prototype Limitations
The prediction engine and truth engine in this prototype are deterministic baselines intended to demonstrate the AI evidence architecture. We do not claim real-world ML prediction accuracy for the baseline formulas used in this demo.

## 15. Future ML Improvements
The pipeline is designed so that the deterministic baseline models in `prediction_engine.py` and `truth_engine.py` can be seamlessly replaced by trained AI models (e.g., XGBoost, PyTorch) once historical training data is secured, without changing the architecture.
